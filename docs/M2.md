# M2 — file-based memory

## Delivered

- Hub workspace pull: `~/agents/<agent>/` (62 files on the real hub), excluding
  `.git`, `skills`, `.clawhub`, `.dreams`, `node_modules`.
- Path rewrite on materialise and push:
  `/home/matrix2305/agents` ⇄ `~/agents`.
- Three-way materialise: a local file modified after the last pull is kept, never
  overwritten; hub changes apply only when the local copy is unchanged.
- `context` + `compaction` hooks inject a `<opencode-node-memory>` block for the
  session's agent (SOUL, IDENTITY, USER, AGENTS, MEMORY, project memory, today's
  daily file), capped at `memory.maxInjectBytes`.
- Tools: `memory_search`, `memory_get`, `memory_store`, `memory_push`.
- Conflict-safe push:
  - upload only files whose local hash differs from `localSha`;
  - fetch the remote file first; if it changed since the pull, write
    `.conflict-<node>-<timestamp>` locally and do not overwrite the hub;
  - no deletion propagation.
- Background push timer (`memory.pushIntervalSeconds`, default 300s).
- CLI `oc-node push`, `status` shows memory files and pending changes.

## Limits

- Keyword search only (no embeddings); vector memory is a separate backend.
- Memory is injected only for agents that have a matching `~/agents/<id>`
  workspace (genesis2, lawyer-ai, main, muzej-jugoslavije). Built-in agents get
  no injection.
- Deletions are not propagated from node to hub.
- Conflict resolution is "keep both", not automatic merge.
- The running server must be restarted to pick up the newest plugin tool
  definitions after an in-place update.
