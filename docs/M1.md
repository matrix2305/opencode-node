# M1 — config, CLI, cache-first

## Delivered

- `~/.config/opencode-node/config.json` with `passwordRef`
  (`keychain:`, `secret:`, `file:`, `env:`).
- `~/.local/share/opencode-node/snapshot.json` — cached setup + hashes.
- `~/.local/share/opencode-node/applied.json` — what the local server last applied.
- CLI: `init`, `pull`, `status`, `doctor`, `config`, `restart`.
- Cache-first plugin: applies the snapshot synchronously, refreshes in background.
- Full pull: 9 skills, 3 agents, 2 commands, 1 MCP, raw hub `opencode.jsonc`.
- Config apply preserves the node plugin entry and removes the legacy
  `opencode.json` so only one config document is active.
- Backups before every overwrite.

## Known limits

- First start after config sync can be slow because the hub config enables
  third-party plugins that OpenCode installs on startup.
- `auth.json` (provider credentials stored outside config) is **not** synced.
  Providers configured inline in `opencode.jsonc` are.
- Plugins themselves cannot be registered at runtime; they come from config and
  need a restart.
- Memory is not implemented yet.
- Session state and `opencode.db` are intentionally never synced.
