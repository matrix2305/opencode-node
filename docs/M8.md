# M8 — memory is folder sync only

## Decision

The hub already installs a memory plugin through config sync. This node plugin
must not duplicate its semantics (search, storage, prompt injection). It only
keeps the memory folders in sync.

## Removed

- `context` and `compaction` memory injection hooks.
- Tools: `memory_search`, `memory_get`, `memory_store`, `memory_push`.
- `memory.maxInjectBytes`, `memory.pushIntervalSeconds`.
- `buildMemoryBlock`, `searchMemory`, `storeMemory` from `src/memory.ts` and
  their tests.

## Kept / added

- Bidirectional folder mirror of `~/agents/<agent>/` with path rewriting.
- Three-way materialise (local edits win, remote applies only when local is
  unchanged).
- Conflict-safe push: `.conflict-<node>-<timestamp>` when both sides changed.
- Automatic scan/push every `memory.syncIntervalSeconds` (default 10 s),
  skipping the push when nothing is pending.
- `node.sync` tool and RPC `sync` now pull **and** push pending memory.
- RPC `push` and `oc-node push` remain for manual sync.
- Status/TUI still show memory file count and pending changes.

## Why

The memory plugin from the hub config (`opencode-mem` or any replacement) is
installed by `sync.config` and provides its own tools. Keeping a second memory
implementation caused duplicate tools and prompt bloat.

## Verified

- `npm test` 13/13 after removing the memory-semantic tests.
- `tsc` clean; build clean.
- Pending detection test: a locally edited file is reported until pushed.

## Notes

- The active hub owns `~/agents`; switching hubs with `oc-node hub use` should
  be followed by `oc-node pull` so the folder reflects the new hub.
- Config sync (`oc-node config --mode auto` / `oc-node pull --config`) is what
  installs the hub's memory plugin on this node.
