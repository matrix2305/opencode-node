# M4 — RPC + live TUI

## Delivered

- `src/rpc.ts` defines `matrix2305.opencode-node` with:
  - methods `status`, `sync`, `push` (empty input, object output)
  - event `updated` (`kind: "sync" | "push"`, `summary`)
- Server registers the RPC in `setup` and emits `updated` after:
  - background/forced refresh,
  - tool `memory_push`,
  - timer push.
- TUI part (`src/tui.ts`) now uses `context.client.rpc(NodeRpc)` instead of
  reading snapshot files:
  - startup toast: connected + skill/memory counts
  - event subscription: toast on sync/push, warning when memory stays pending
  - palette commands:
    - **opencode-node: status** — dialog with live hub/cache/counts/memory
    - **opencode-node: sync now** — pull + toast
    - **opencode-node: push memory** — push + conflict/upload toast
- `./rpc` export for other clients/plugins.

## HTTP shape

The server expects `{ "input": { ... } }` and a location query:

```bash
curl -u opencode:<password> -X POST \
  -H 'Content-Type: application/json' \
  -d '{"input":{}}' \
  'http://127.0.0.1:49374/api/rpc/matrix2305.opencode-node/status?location[directory]=/home/me'
```

## Verified

Isolated server (dist build):

```
status -> {"output":{"hub":"...","counts":{"skills":9,"agents":3,...},"memory":{"files":62,"pending":[]}}}
push   -> {"output":{"uploaded":[],"conflicts":[],"unchanged":62}}
```

Live server: RPC status returns the same summary after the hot reload.

## Notes

- TUI `context.client.rpc` binds the current location automatically; HTTP callers
  must pass `location[directory]`.
- The TUI part has no JSX/OpenTUI peers; a footer slot is still deferred.
- RPC registrations are disposed with the plugin; a restart reloads tool and
  command definitions cleanly.
