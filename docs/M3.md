# M3 — TUI, build, publish

## Delivered

- `dist/` build via tsup: `index.js` (server), `tui.js` (terminal), `cli.js`
  (CLI with shebang and executable bit).
- Package exports:
  - `.` → `dist/index.js`
  - `./tui` → `dist/tui.js`
  - `./cli` → `dist/cli.js`
  - `bin.oc-node` → `dist/cli.js`
- Server slash commands:
  - `/node-status` — synthetic message with hub/cache/counts/memory state.
  - `/node-sync` — force pull + synthetic summary.
  - `/node-push` — push memory + synthetic result.
- TUI part (`src/tui.ts`):
  - palette command **opencode-node: status**
  - slash command `/node-status`
  - dialog with hub, cache age, counts, memory files
  - reads the local snapshot; no JSX/OpenTUI peer dependencies.
- Tests (`node:test`, 10 passing): JSONC insertion, path rewrite, materialise
  keeping local edits, store/search, memory block cap/agent matching.
- CI workflow: typecheck, tests, build, `npm pack --dry-run` on Node 24.
- LICENSE (MIT), `docs/COMPATIBILITY.md`, `docs/PUBLISH.md`, `CHANGELOG.md`.
- Version `0.1.0`, scope `@matrix2305`.

## Verified

- Isolated server with the package root as `plugins` entry: loads
  `dist/index.js`, pulls 9 skills / 3 agents / 2 commands / 62 memory files.
- `node dist/cli.js status` and direct `./dist/cli.js` both work.
- `npm test` — 10/10.
- `tsup` output sizes: index ~31 KB, cli ~31 KB, tui ~2 KB.

## Notes

- The TUI part is read-only status; sync/push stay on the server side so they
  work with remote hubs too.
- TUI footer slot (`home.footer.status`) is possible but needs Solid/OpenTUI
  peers; deferred to keep 0.1.0 dependency-free.
- After upgrading the package in place, restart OpenCode so tool/command
  definitions reload.
