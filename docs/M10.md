# M10 — provider credentials sync

## Problem

`applyConfig` copies provider definitions from the hub `opencode.jsonc`, but the
API keys saved by `opencode auth login` live in `~/.local/share/opencode/auth.json`,
which was never synced. A synced provider therefore appeared in the model list
with no usable key.

## Delivered

`sync.auth` (default on):

- `pull` reads the hub's `.local/share/opencode/auth.json` through `/api/fs/read`
  into `snapshot.auth` (`entries` + `sha`); credentials are never logged.
- `applyAuth(snapshot)` merges hub entries into the local `auth.json`:
  - hub wins for providers it defines (that is the point of config sync);
  - local-only providers are untouched;
  - idempotent — matching entries are skipped;
  - backup before write, atomic rename, mode `0600`.
- Applied by `oc-node init`, `oc-node pull`, and prints the merged provider list.
- `oc-node status` shows how many credentials the hub provides.

## Verified

Real hub (`matrix2305`):

```
auth:     2 provider credential(s) on the hub
auth:     1 credential(s) merged (opencode-go) · restart to use them
local auth.json: opencode-go key updated, 15 local providers intact, mode 0600
```

Unit tests: merge keeps local-only, idempotency, creates the file when missing
(19 total).

## Notes

- `zai-coding-plan` already matched locally, so only `opencode-go` merged.
- Push of credentials node → hub is intentionally **not** implemented; the hub
  is the source of truth for keys.
- Restart OpenCode after a merge for the providers to become usable.
