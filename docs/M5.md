# M5 — config/providers sync modes

## Delivered

`sync.config` now understands three modes:

| Mode | Behavior |
| --- | --- |
| `false` (`off`) | never touch the local config |
| `"manual"` | only `oc-node config` / `oc-node pull --config` |
| `"auto"` | the plugin writes the hub `opencode.jsonc` when its hash changes |

Legacy boolean `true` is normalized to `"manual"` for safety; `false` stays
`false`. Default for new configs is `"manual"`.

CLI:

```bash
oc-node config --mode auto      # set + apply now
oc-node config --mode manual    # apply only on demand
oc-node config --mode off       # disable
oc-node config --dry-run        # show target + hub hash
oc-node config                  # apply the current snapshot
oc-node status                  # shows config mode + drift
oc-node doctor                  # includes config mode
```

Auto apply runs:

- 1.5 s after setup when a cached snapshot exists (so setup is not blocked),
- after every successful background/forced refresh when `config` hash changed.

Each apply:

- writes the hub config to `~/.config/opencode/opencode.jsonc` (mode 0600),
- keeps the node plugin entry,
- removes the legacy `opencode.json` (backup kept),
- records `applied.config`,
- logs `config:auto-applied` and emits RPC `updated` with `kind: "config"`.

## Notes

- Config is applied for the next server start; depending on the host, OpenCode
  may hot-reload the file immediately. A restart (`oc-node restart`) guarantees a
  clean load.
- Provider credentials stored in `auth.json` are **not** synced. Providers whose
  keys are inline in `opencode.jsonc` are.
- Every apply keeps a timestamped backup; `oc-node restore` rolls back.
- Auto mode can change models/providers mid-session if the host hot-reloads the
  config. Use `manual` if that is not desired.
