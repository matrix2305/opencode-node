# M11 — credentials live in the server, not in files

## Why

M10 wrote hub keys into `~/.local/share/opencode/auth.json`. Two problems showed
up in practice:

1. The running server ignores that file until a restart — the user still hit
   "API key has expired" because the server kept the old in-memory credential.
2. Duplicating key material into another file widens the surface for leaks.

## Delivered

- `src/auth.ts`:
  - `fetchAuth(hub)` reads the hub's `auth.json` over `/api/fs/read` (memory
    only, never logged).
  - `applyAuthMemory()` connects each provider credential with a stable label
    `opencode-node:<hub>`; optional `list`/`remove` hooks replace old
    hub-labelled credentials instead of stacking.
  - `applyAuthViaLocalServer()` CLI variant using the local server's HTTP API
    (`/api/integration/<id>/connect/key`, `/api/credential`).
- Server plugin (`src/server.ts`): `applyAuthLive()` runs after the cache load
  and after every background refresh via `ctx.integration.connect.key`.
- CLI: `init` and `pull` connect credentials live; `status` prints the hub
  credential count.
- Snapshot no longer stores key material — only `authCount` and a hash of
  provider names (`hashes.auth`).
- `applyAuth` (file merge) removed; tests rewritten for the memory flow (19/19).

## Verified on the live server

```
oc-node pull
auth:     2 provider credential(s) on the hub (applied to the local server, not stored in files)
auth:     2 connected (opencode-go, zai-coding-plan)

opencode run -m opencode-go/deepseek-v4.1-flash → ok-live / final-ok
```

Also verified with `auth.json` emptied (backup kept): the model still works,
proving nothing depends on the file anymore.

## Notes

- The expired OpenCode Console credential from earlier sessions remains removed
  (`auth logout`); stale in-memory credentials of disabled providers disappear
  on the next server restart.
- Node → hub credential push is intentionally not implemented: the hub is the
  source of truth.
