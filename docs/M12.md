# M12 — model list parity with the hub

## Why

After config sync, the local server still listed models from old local
providers (neuralwatt, moonshot-era, deepseek direct, openrouter …), so the
model picker showed entries that could not be used and diverged from the hub.

## Delivered

- `pull` now reads `GET /api/model` from the hub (with location) into
  `snapshot.models` (`providerID`, `id`, `ref`, optional name/hidden/enabled).
  The snapshot hash `hashes.models` covers the reference list.
- The server plugin applies the hub list at runtime with `ctx.model.transform`:
  every local model whose `provider/model` reference is not in the hub list is
  set `enabled: false` (disabled, not deleted — a later hub change can re-enable
  it). Runs after the cache load and after every background refresh.
- `oc-node pull`/`status` print the hub model count; RPC/TUI `status` shows
  `models` in counts; the TUI dialog notes that local-only models are disabled.

## Verified (live)

```
oc-node pull → models: 69 from the hub
opencode models → 69 entries
diff <(local models) <(hub /api/model) → empty (identical lists)
neuralwatt/* → absent from the picker
opencode run -m opencode-go/deepseek-v4.1-flash → model-ok
```

## Notes

- Disabled models remain in the registry (`enabled: false`); nothing is deleted,
  and `oc-node restore` is unaffected.
- If the hub later adds a model back, the next refresh re-enables it (the
  transform only disables models missing from the hub list).
- Custom local models defined in the local config are also disabled by design;
  whitelist them on the hub or set `sync.config` accordingly.
