# M9 — plugins are pulled during install

## Delivered

`sync.plugins` (default `true`) makes the plugin layer part of the pull:

- **Plugin list** — read from the hub config (`plugins` and legacy `plugin`
  arrays in every config document). Values are kept verbatim, including the
  object form `{ "package": "...", "options": { ... } }`.
- **Local plugin files** — `~/.config/opencode/plugin/` and `plugins/` trees are
  copied (nested directories included, `node_modules`/`.git` skipped).
- **`package.json`** — the hub file is merged with the local one; dependencies
  are unioned, local wins on conflicts, other local fields are preserved.
- **Merge semantics** — hub entries are appended to the local `plugins` array.
  Local entries are never removed. Merging is idempotent and works on
  commented JSONC without rewriting the file.

Applied by:

- `oc-node init` (right after the first pull),
- `oc-node pull`,
- the server plugin on startup (cache-first) and after every background refresh
  (emits RPC `plugins`, TUI toast "plugins synced · restart OpenCode").

## Notes

- The hub's `plugins` list is authoritative only for *additions*. Removing a
  plugin from the hub does not remove it locally; delete it from the local
  config, or use `oc-node restore` for a full rollback.
- Plugin code changes only take effect after OpenCode installs and loads them
  (restart or `opencode reload`).
- `sync.plugins = false` keeps the old behavior (no plugin merge, no plugin file
  copy).
- Skills from the hub plugin (`claude-code-plugin`, `history-recall`) appear
  automatically once the plugin loads.
